# v1.4.0 更新执行规则

## 1.4.0 当前执行规则（2026-11-05）

必须仅在当前聊天的 Codex 内置浏览器打开并操作 BOSS；禁止 BOSS 客户端、Edge、Chrome 和系统默认浏览器回退。先用 Codex open_in_codex 的 browser target 复用当前 BOSS tab 或打开 https://www.zhipin.com/，从实际返回结果取得 tabId，禁止自造。随后运行 scripts/bind-boss-browser.ps1 -WindowHandle <当前Codex窗口> -ChatTitle <本聊天准确标题> -TabId <实际返回tabId> -OutputFile <本轮binding.json>，并给 workflow_runner --browser-binding <该文件>。单步恢复及独立辅助命令以 BOSS_BROWSER_BINDING 指向同一文件。tabId是打开入口的关联标识；UIA校验Codex宿主进程/创建时间、本聊天可见文档、唯一BOSS顶层文档及后续目标祖先。无法唯一核验则待重绑定，禁止退回整窗口搜索或外部浏览器。

BOSS右上角岗位/公司名与skill岗位不一致只提示；信任人工选择，不禁止、不切换、不再次确认。候选规则与日表归属继续使用所选skill快照，可将页面实际名称作为事实单独记录，未知不编造。

全岗位共享首条预留起500秒最多10人的固定窗口；满10人后第11人等待到窗口结束。旧窗口保留起点、用量及占位，不因更新/重启/切岗清零，未知发送保守占位，同次重试及后续句不重复计人。

短查看随机等待默认开，可用 --no-short-view-wait 关闭，或在悬浮窗切换；仅影响随机等待，不取消10分钟限额。包括关键词未命中/同事跳过，每位处理<30秒则切下一位前额外随机20–40秒；处理时间扣暂停和已有等待，恰好30秒不触发，最后一位不额外等待。随机抽样和截止时间按访问持久保存，暂停/重启不重抽；关闭取消当前随机等待，重开不补等；与额度等待取较晚截止时间。

新普工运行使用worker_resume，旧card历史不改写：列表按原优势/期望词表初筛→命中才开电子简历→全文重新匹配原词表→命中后查同事记录。明确无记录或所有记录完整且严格>7天可招呼；任一<=7天跳过；异常未知不当作无记录。全文否定/广告/引用不算命中，无评分门槛。详情处理后直接下一份简历；可读正文未命中累加，命中即清零（包括随后因同事跳过），连续5份未命中Esc回列表继续初筛；不可读有界恢复后真实记录且不计miss。浏览阶段、miss和返回位置跨候选/重启保留；无法核验下一人则回列表。列表→首份详情共用一次查看/计时/随机等待，未查同事的未命中记录不得被改成同事未知，发送前必须通过同事检查。

DOMAIN关键词命中仍需完成当前快照评分；优先定向UIA TextPattern全文，必要时定向滚动聚合，OCR仍可选。保留现有A/B组合关键词通道及配置评分公式，不用默认quick_base伪装实际评分。硬条件通过AND（有效关键词命中OR实际分达到阈值）；记录、资格复核、发送和收藏使用同一评分。实际>=90才收藏，未知分不收藏，不修改其他岗位评分。

Excel顶部所有摘要合为一行，不换行，包含目标岗位、查看/招呼人数、时长/平均、版本/上海更新时间。标题第2行、数据第3行、冻结C3；同日同岗一份原文件、隐藏证据和链接保留，文件占用按原pending补写。
