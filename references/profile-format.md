# 岗位标准化文件格式 v1

新岗位输出到本 Skill 的 `profiles/<企业>/<岗位>/<企业-岗位-标准化信息.md>`，每个岗位目录独立配置 `project.json`。既有岗位保持原路径，不因新增企业分组迁移或改写。企业法定全称不明确时沿用资料明确名称并在正文注明主体待确认，不补造公司后缀。原始资料目录只读；文件为 UTF-8 Markdown，开头使用以下简单 front matter。字段名保持不变，值不含换行：

```yaml
---
schema: boss-greeting-profile/v1
company: 企业全称
position: 岗位名称
source_root: 原始企业资料文件夹的绝对路径
approval: pending
approved_by:
approved_at:
---
```

正文固定包含这些二级标题：

- `## 页面核验`：执行前必须从当前页面确认的企业、岗位、城市；资料缺失时说明。
- `## 企业与岗位事实`：职责、办公地、薪酬和其他经资料支持的信息，并标出不能承诺的细节。
- `## 自动筛选条件`：逐项写明“符合 / 明确不符 / 信息不足”的判定依据。未决冲突涉及的条件不得作为自动通过依据。
- `## 评分规则`：列出岗位相关维度及 0–100 分锚点，说明列表、电子简历、附件各自如何评分与综合分如何形成。默认综合分至少 70 且所有硬条件明确符合；分数不能代替硬条件。未看过的材料不打分。评分口径须随岗位文件一起确认。
- `## 加分项`：只能提升排序，不能代替硬条件。
- `## 待人工确认`：简历无法核实的资格、具体待遇或安排。
- `## 固定招呼话术`：待用户核准的完整文本和发送顺序。需要按姓名称呼的第三句可使用 `{{称谓}}`：从已打开的电子简历读取完整姓名，提取姓氏；页面明确显示“男/女”或“先生/女士”时分别填“X先生/X女士”，否则填“您好”。不得凭姓名、照片或截断的卡片名称猜测性别。模板不要为称谓加括号，直接写 `{{称谓}}，感兴趣的话可以发送一下您的简历，我们聊聊`；无需针对个人经历生成新的事实。
- `## 冲突与待确认`：每项使用 `- [ ]`；确认后将结论、确认人、日期写在同项并改为 `- [x]`。没有冲突时写“无”。
- `## 来源`：列出 `source_root` 下的文件名及支持的字段或章节。

只有 `approval: approved` 且全文不存在未勾选的 `- [ ]` 时，执行 Skill 才能使用。用户确认的是整份文件的当前版本；变更关键事实、筛选条件或话术会使确认失效。
