# 运行控制策略（1.1.1，2026-10-31）

本文件记录用户对限制清单的11条批注，是当前唯一的控制口径；历史日志保留原文，旧文档的相反约束不再执行。

| 批注 | 实际变更 |
|---|---|
| 1 | 招呼默认150，可指定更大的任意正整数，无固定150上限 |
| 2 | 查看默认300，新增--max-views，可指定更大正整数 |
| 3 | 删除3/4小时、自然截止、暂停不延长截止等限制 |
| 4 | 删除滚动24小时额度限制 |
| 5 | 不恢复60秒固定间隔或随机冷却，旧next_allowed_at忽略；按2026-10-31新要求，所有岗位共用每5分钟最多10人的固定窗口，仅满额时等待剩余时间 |
| 6 | 未审核及配置待确认仅提醒，不阻止正常执行 |
| 7 | 不再必须绑定或探测当前聊天停止按钮；有绑定时可用于便利中断 |
| 8 | 删除报表同步、证据归档、候选登记/计时/收尾及完整截图/OCR的继续门槛 |
| 9 | 卡片状态未知不暂停；页面加载/文档异常允许有界自动恢复 |
| 10 | 删除稳定候选ID的历史去重，独立查看保留独立访问记录 |
| 11 | unknown不再要求人工核销或全局阻塞；删除每动作状态/候选归属/凭据守卫 |

保留：首次推荐页人工筛选确认、同事去重、岗位匹配、运行中岗位文件变化检查、悬浮窗、默认单次招呼、UIA工具方式和键盘焦点要求、禁点举报/不合适/删除、平台验证码与账号限制、真实记录。

“无固定上限”指可覆盖默认数量；本次明确目标仍是停止条件。暂停/结束由控制器和运行编排执行，操作入口不再重复查运行状态，不将删除的守卫换名加回。

账本访问键用于区分同一候选人的多次处理，不是伪造候选人身份；candidate_visits保留原始candidate_id。历史表结构、旧记录与旧快照保留，旧时长/24小时额度/固定间隔不再执行。

2026-10-31新增统一限速：从本窗首条招呼开始计300秒，每窗最多10人；未满10人不添加间隔，超过300秒的慢处理自然进入新窗，不额外休息或积累空闲额度。计数按本机同一账本跨岗位、运行和进程共享并持久化；在首条预留及实际发送入口检查，未知结果保守占位，同次重试和三连后续句不增加人数。重启或切换岗位不能清零。主执行器返回rate_limited并自动等候，仍响应暂停/结束；单步命令返回retry_at和retry_after_seconds供原步骤续接。此限速是用户本次明确新增的要求，优先于历史“无冷却”描述。

unknown处理：读取当前平台状态，可确认成功则记sent；明确仍可招呼时允许一次自动重试；仍不明则记unknown并继续。不能把“派发”写成“成功”。

1.0.13已接入更新计划功能，详见[plan-features.md](plan-features.md)。上述删改不回退；同事检查优先于分析，OCR仍可选。

1.0.14：主循环统一暂停/继续/结束，不恢复逐动作守卫。真正重新打开仍算新访问，补写及发送重试不再增加查看数。默认数量联动及其他六项优化见[continuous-workflow.md](continuous-workflow.md)。
