# 1.4.16-beta 当前执行契约

真实运行、恢复或核对候选流程时读取本文件；历史 `v1.x-policy.md` 只用于旧快照兼容，不覆盖当前岗位 MD、项目快照或本契约。

## 入口与启动

- 从桌面 `自动招呼/02 招呼配置` 读取有效岗位 MD，记录写入 `自动招呼/01 招呼记录`；不从旧 profiles 猜岗位。进入菜单或列表后先核对返回的 `config_root` 必须是该桌面目录；缺少该字段或指向源码 `profiles` 时，说明调用了旧源码入口，必须停止并切换运行包后重读，不得报告“暂无项目”。
- 用 `scripts/project_registry.py menu` 选择/创建项目，再由 `quick_start.py` / `workflow_runner.py` 执行。企业和岗位唯一匹配时，用户给出的正整数人数即本轮授权；歧义时保留人数并先选岗，不猜测。
- 用户没有明确企业或岗位时先展示菜单1并保留人数，不沿用上次岗位。
- 主菜单为继续上次、查看企业、创建项目、更新项目、测试、退出；“菜单1”是首页，“菜单2”进企业选择，首页回复 1 才继续上次。
- 默认成功招呼 150、查看 300；岗位默认最低查看 30 秒、每 5 次成功后休息 30 秒、同事阈值 7 天、单句、AI总评关闭、扣分整体复盘开启；实际岗位 MD 已确认值优先，历史快照不改。

## 页面与安全

- 后台 Win32 UIA 负责页面读取、点击、滚动、输入、打开/关闭简历、同事记录、招呼、核验和收藏，不自动前置窗口。只有原本需要前台的截图交给 [浏览器](plugin://browser@openai-bundled)。
- 绑定实际 `tab_id` 和 BOSS HTTPS URL；`workflow_runner` 默认使用 `HybridAdapter`。UIA 动作在后台直接执行，截图由 `workflow_handoff.py` 返回 `needs_browser`，一次请求完成多页滚动与截图后再本地拼接 OCR。
- 每次 UIA 动作后重新查询实际页面状态；浏览器截图请求须确认同一候选人、正文视口、滚动偏移和完整性。旧坐标、节点标识不跨页面复用。悬浮窗和本地报表仍在本机运行。
- BOSS 右上角显示的公司/岗位与本轮目标岗位不一致时，只在当前聊天框做一次 `🔴` 提示，包含页面实际名称和目标名称（名称不可读时不编造）；不切换岗位、不再次确认、不暂停或重启，继续沿用户选定岗位的岗位 MD 和规则快照执行。一次运行内不得按候选人重复提示。
- 验证码、退出、发送限制、页面失联、无法定位或证据不完整时暂停/有界恢复并记录；禁止举报、不合适、删除、绕过验证；未知结果不得写成功。

## 候选门槛

1. 列表读取整卡并按岗位词库初筛；未命中或列表扣分低于门槛跳过，不开简历；空正向列表不限制，不另建历史身份指纹。
2. 开简历先查平台按钮；“继续沟通/继续打招呼”跳过，不重复发送。
3. 截图前查同事：配置 0 不查询；阈值内记录跳过；全部超阈值且完整或明确无记录才继续。同事判断从开始起累计5秒，查询、点击、重试共用预算；只要超过5秒，无论结果为无法判断、读取失败或其他异常，统一按超时静默跳过并继续正文采集和岗位评分，不逐人输出对话提醒，也不把超时记成无记录。
4. 之后滚动截图、拼接长图、本地 OCR 和完整性核验；合并正文、期望岗位、个人优势、经历概览及全部实际可读材料；正文为空或较短不作为不完整依据。存在未采集区域、遮挡、采集失败或材料变化时，待复核且不发送。
   短简历无滚动区域时，核实简历文档、可见边界、内容加载和前后稳定性后采用单屏截图/OCR；不可仅因无滚动条或无法滚动判为不完整。存在隐藏、越界、加载中或文档变化时仍不放行。截图必须来自插件，保存 JPEG 原图；拼接、OCR 仍在本地完成。
5. 按岗位 MD 组合评分：单组门槛 60、多组同时命中门槛 70；首词 60/70 起，每个不同正向词 +2、封顶 100；不同减分词 -10、最低 0；否定/招聘引用不算经历命中。
6. 正向规则未过不调用 AI；扣分后低于门槛且开关开启时，AI 只按完整材料返回 `suitable/reason/pros/cons/quotes`，不得改分。
7. 发送前复核材料、规则、复盘和平台状态；默认单句，三句须有配置和话术。平台核验成功才计成功；未知仅在明确仍可发送时最多重试一次。分数 ≥90 才收藏；未知分、同事跳过不收藏。

## 交接与收尾

- 新建运行前先停止未结束的旧运行，并按进程创建时间核验后关闭其已登记执行器和悬浮窗；恢复同一运行不关闭自身、不重复创建悬浮窗。旧运行报表整理失败保留待补状态，不冒充成功。
- 任务停止状态成功持久化后，报表整理失败仍允许关闭窗口；下次启动重试整理。清理旧运行不调用 Codex 聊天停止按钮。

- 一个运行只保留一个 `workflow_runner`；用 `scripts/workflow_handoff.py --run <run_id> --timeout 45` 只读等待交接，不重复启动。`needs_summary` / `needs_overall_review` 只写已读事实。
- 同事/筛选提醒必须先在当前对话展示，再登记 `displayed:true`；`needs_filter_notice` 的 message 必须展示，无数字或 0 时提醒未筛选，相同状态不刷屏。
- `run_id`、候选阶段、等待/休息和暂停状态持久保存；列表判断计已判断，确认开简历才计已查看。每岗位每上海自然日维护报表，但最终询问打开的是带说明的快照 Excel；原图/标记图/OCR JSON 保留。
- 达到目标、查看上限等自动完成不中断当前聊天，也不弹P1中断失败提示。退出时不执行浏览器缩放还原，保留当前缩放。报表、归档、刷新失败记待补且不阻塞主流程；结束先停止、同步、收尾，再询问是否打开快照表格，只有用户选择是才打开。
