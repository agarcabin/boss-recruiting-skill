## 结论

1. 当前 UIA 只能读取右侧经历概览和基础信息，无法读取中间工作职责正文。
2. `c-resume` frameLocator 路径连续三次导致页面重建，当前内置浏览器环境下不可用。
3. 网络响应监听接口不支持 `response` 事件，无法通过 Playwright 包装接口捕获简历 JSON。
4. 没有可定位的可见打印入口，未使用被 skill 禁止的 `Ctrl+P`。
5. UIA 鼠标拖选 + 剪贴板可以读取中间正文的可见部分。配合滚动，两屏共复制 `648` 个纯文本字符，比 OCR 准确且速度更快，但目前还没有证明能一次覆盖完整简历。
6. 截图 + Windows 本地 OCR 可以读取中间正文。两屏共提取约 `2,918` 个字符，覆盖范围更大，但存在 OCR 错字。
7. 当前可实际落地的方法只有两种：UIA 拖选复制和截图 OCR。前者准确、低 token；后者覆盖更完整，但耗时和 token 更高，并需要文本纠错。
8. 额外探测 `dom_cua.get_visible_dom()`：当前 IAB 运行时未暴露该成员，调用返回 `undefined`，不可用，且未触发刷新。
9. UIA 定位专项诊断确认：`FromPoint` 命中 Codex 覆盖层，而点击后的 `FocusedElement` 能进入 `c-resume`；但 `c-resume` 正文没有 Text 子控件，属于定位层和可访问性层同时存在问题。详见 [UIA 定位诊断报告](uia-resume-diagnostic-report.md)。
10. V2 生产路线确定为 UIA 内层滚动、固定视口截图、长图拼接、本地 RapidOCR 分块识别；已发送候选人的长图、OCR 文本和 OCR JSON 必须归档，并与 PDF 一起阻止进入下一候选人。
