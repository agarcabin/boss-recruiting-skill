# 简历截图与本地 OCR（1.4.16-beta）

正文读取和页面控件操作优先使用后台 UIA；截图使用用户指定的 [浏览器](plugin://browser@openai-bundled)。一个截图请求连续滚动并采集多页，完成后一次性回填，见 [浏览器交接契约](browser-plugin.md)。没有滚动区域时先采集单屏候选，本地OCR出现“牛人”即确认到达底部；未出现则待复核。若用户明确关闭 OCR，则无需截图请求，按已核验的 UIA 完整正文继续。

## 采集顺序

列表初筛 → UIA 打开同一候选人简历 → 平台已招呼状态 → 同事检查 → UIA 读取全部实际可读材料 → **一次浏览器截图请求**滚动采集正文 → 本地拼接、OCR、完整性核验 → 评分。正文、期望岗位、个人优势、经历概览及工作/教育/项目经历合并；不因正文为空或字少判不完整。

截图原样保存 JPEG 至 capture 请求分配的唯一 output_dir。只截正文滚动视口，排除固定页头和侧栏；记录实际滚动偏移，连续覆盖，不猜偏移。确认顶部、底部、加载完成、同一候选人及内容稳定后才声明完成。无滚动条的短简历允许单屏，但同样需要完整可见、无隐藏和遮挡的证据。

后台 capture_resume.import_browser_capture 校验候选人、完整标记、文件归属、图像宽度、偏移连续性和尺寸，再运行本地 resume_image_pipeline.py stitch 及 rapidocr。原图、resume-capture.json、resume-long.png、resume.ocr.txt 和 resume.ocr.json 全部保留本地。OCR 使用 1200 像素分块、150 像素重叠，字符框仍用于后续实际命中词标注。

未到正文底部、存在隐藏区域/加载中/推荐遮挡、候选人变化、文件缺失、偏移不连续或 OCR 失败时，不放行评分发送。不得把列表卡片或经历摘要当完整简历。用户明确关闭 OCR 时才用 --no-ocr，仍需通过插件完整阅读和核实材料。

暂停、停止或截图请求过期后不派发待办截图。恢复继续同一运行，以 UIA 和浏览器新证据重新核查；不会自动重放旧点击或向全局桌面派发输入。
