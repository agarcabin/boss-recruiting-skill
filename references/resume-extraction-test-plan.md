# 电子简历完整正文提取测试计划

本文件保留历史对比测试用例。以下 DOM、整页 AX、JavaScript、剪贴板和 getAXState 方案仅用于解释为何被淘汰，不得在生产流程重新执行。当前生产流程只允许定向 UIA，以及电子简历正文的 [长截图与 RapidOCR](resume-capture-ocr.md)。

定位诊断结果见 [UIA 定位诊断报告](uia-resume-diagnostic-report.md)。

## 目标

在 Codex 内置浏览器中读取 BOSS 电子简历 `c-resume` 的主内容区，特别是中间的完整工作经历、职责和业绩。测试只读取简历，不发送招呼，不修改候选人数据。

## 安全与恢复规则

任何一步出现下列任一情况，立即停止当前测试和页面操作：

- `c-resume` Document 消失。
- 推荐 iframe 出现 `jobid=null` 或 `about:blank`。
- 可见“打招呼”按钮数量异常归零。
- 页面重新出现“加载中，请稍候”。
- 浏览器标签页被重建。

停止后记录最后执行的方法、页面特征、耗时和输出大小，不自动重试、不自动刷新。通知用户重新打开电子简历，用户回复 `1` 后先重新核验 `c-resume`、岗位和候选人，再从下一个未执行用例继续。

## 指标

每个测试记录：

- 纯方法耗时：从查询或脚本开始，到结果返回。
- 端到端耗时：包含等待页面、重新打开简历和恢复核验。
- 输出字符数：工具实际返回给模型的文本长度。
- 估算 token：中文字符数 + 英文字符数 / 4，向上取整。
- 提取字符数：方法实际从页面读取到的简历文本长度。
- 是否取得中间正文：必须包含工作职责、业绩或项目描述，而不是只有右侧概览。
- 是否触发页面重建。

## 前置条件

1. Codex 保持最大化，内置浏览器可见。
2. BOSS 当前岗位为“销售专员 _ 宁波 12-17K”。
3. 推荐 iframe 的 `jobid` 非空。
4. 用户已手动打开一份电子简历。
5. 当前 `c-resume` Document 存在。
6. 测试期间不发送招呼、不点击不合适或举报。

## 执行规则

1. 一次只执行一个测试。
2. 每个测试前记录开始时间和页面状态。
3. 每个测试后输出结果摘要，不输出完整简历正文。
4. 原始简历文本只保存在内存或临时文件，测试结束后删除。
5. 如果测试触发刷新，立即进入恢复流程并从该测试重新开始，不跳到后续测试。
6. 同一方法连续失败两次后标记为不可用，不反复尝试。
