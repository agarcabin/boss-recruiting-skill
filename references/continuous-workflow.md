# 连续执行

现行规则统一见根目录SKILL.md，岗位词库与配置见当前桌面岗位MD。历史版本参考只用于回溯，不叠加到新任务。

启动顺序：后台 UIA 复用当前聊天BOSS页面，并记录 [浏览器](plugin://browser@openai-bundled) 的当前标签页供截图 → 创建/续接运行 → 核验本轮悬浮窗 → 使用HybridAdapter的唯一workflow_runner。页面读取和交互留在后台，只有截图进入 [浏览器交接契约](browser-plugin.md)。

候选顺序：列表初筛 → 打开简历并检查平台招呼按钮 → 同事检查（最多5秒，超时静默继续） → 截图/OCR及完整性核验 → 关键词计分及每个不同减分词扣10分 → 条件性AI总结/整体复盘 → 发送核验 → 收藏 → 单份最低时长及每5次成功招呼额外休息 → 下一位。

AI总评默认关闭：普通候选项不调用优缺点总结，Excel摘要不展示优缺点列。正向通过但扣分低于合格线且整体复盘开关开启时，仍执行一次needs_overall_review，按完整材料给出suitable、reason、pros、cons及原句quotes，带request_id写回答复文件。规则分数、同事与平台状态仍核验。

主执行器启动后，以包内Python执行scripts/workflow_handoff.py --run <run_id> --timeout 45等待请求。每0.1秒检查一次，有未答请求立即返回，最长45秒；暂停、停止或需要处理的错误立即返回。超时不表示任务完成，不重复启动主执行器。

`needs_browser` 只用于截图。当前模型认领后，在一个请求中完成正文滚动和多页截图并回填；Python后台不能自己调用插件。过期、已认领、已停止或执行器退出的请求不重放。发送等后台UIA动作不回退到浏览器，发送回执丢失时续接verify核查。

筛选提醒必须在当前对话展示后才登记displayed:true。同事记录查询、点击和重试合计5秒；只要超过5秒，无论无法判断、读取失败或其他异常都统一静默跳过，不逐人输出对话提醒，也不能改写为无记录。截图之前核验同事记录，0天配置不查同事。平台显示继续沟通时跳过，不增加额外身份指纹工作。

单份最低查看时间、每5次成功招呼的额外休息均持久记录，暂停不累计；近期同事跳过免最低查看等待。最后一人完成本份最低时长和触发的额外休息后结束。程序阶段、AI总结、AI整体复盘、等待分别留起止及有效耗时。

报表、归档等旁路失败记录待补，不停止主执行器。达到目标或查看上限等自动完成不尝试中断当前聊天。结束先持久停止并完成收尾，再询问是否打开快照Excel，只有选择是才打开。
