# 连续执行

现行规则统一见根目录SKILL.md，岗位词库与配置见当前桌面岗位MD。历史版本参考只用于回溯，不叠加到新任务。

启动顺序：复用并绑定当前聊天BOSS页面 → 收起宿主侧边栏 → 创建/续接运行 → 核验本轮悬浮窗可见 → 布局检查 → workflow_runner。

候选顺序：列表初筛 → 打开简历并检查平台招呼按钮 → 同事检查 → 截图/OCR及完整性核验 → 关键词计分及每个不同减分词扣10分 → 条件性AI总结/整体复盘 → 发送核验 → 收藏 → 单份最低时长及每5次成功招呼额外休息 → 下一位。

正向词库未通过不做AI分析。正向通过但扣分低于合格线时，整体复盘开关关则直接不合格；开则返回needs_overall_review，按完整材料给出suitable、reason、pros、cons及原句quotes，带request_id写回答复文件。合适可放行，规则分数保留，同事与平台状态仍核验。

主执行器启动后，以包内Python执行scripts/workflow_handoff.py --run <run_id> --timeout 45等待请求。每0.1秒检查一次，有未答请求立即返回，最长45秒；暂停、停止或需要处理的错误立即返回。超时不表示任务完成，不重复启动主执行器。

同事异常提醒和筛选提醒必须在当前对话展示后才登记displayed:true；不自动生成提醒回执。截图之前核验同事记录，0天配置不查同事。平台显示继续沟通时跳过，不增加额外身份指纹工作。

单份最低查看时间、每5次成功招呼的额外休息均持久记录，暂停不累计；近期同事跳过免最低查看等待。最后一人完成本份最低时长和触发的额外休息后结束。程序阶段、AI总结、AI整体复盘、等待分别留起止及有效耗时。

报表、归档等旁路失败记录待补，不停止主执行器。结束先持久停止并完成同步，再询问是否打开表格，只有选择是才打开。
