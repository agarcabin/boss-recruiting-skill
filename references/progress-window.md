# 投递进度悬浮窗

`python.exe scripts/launch_progress.py --run <id> --output-root <目录>`，创建运行后仍须确认悬浮窗可见。

控制口径见 [control-policy.md](control-policy.md)。无自然截止和滚动额度，按本次target/max_views判断数量完成；查看预计基线使用当前max_views。

启动自动按招聘标题绑定准确聊天。标题不同于默认时传`--chat-title "准确标题"`，自定义标题即使首次绑定失败也会保存供后续重试。暂停先暂停招聘，再在独立线程中调用对应聊天的停止按钮，等待按钮消失确认；已处于空闲态记idle。按钮改为“请在 Codex中回复‘继续’”并禁用点击恢复。收到继续后对原run执行`python scripts/ledger.py control --run <id> --action resume`，续接原执行器；执行器已退出时从原检查点重新启动，不重建运行。

结束先写停止状态，独立控制器中断Codex并收尾导出。绑定失效时按准确标题重新定位，保留进程、Document和聊天工具栏核验；不依赖重绘后失效的scope RuntimeId。切到其他聊天/无法定位对应聊天时明确提示中断失败，不能误停当前其他聊天，不能声称后台思考已停止。UIA尚不能可靠中断隐藏聊天。此限制不阻止招聘暂停/结束。所有这些后台控制、采集、OCR和UIA子进程设置CREATE_NO_WINDOW及隐藏启动参数，保留stdout/stderr用于诊断。

结束由独立控制器处理：写停止状态、取消本轮登记helper、生成结束快照、关闭悬浮窗并显示Excel。报表或归档欠缺不阻止停止，也不伪造成功或完整证据。状态/按钮文字和计数失败应如实报告。
