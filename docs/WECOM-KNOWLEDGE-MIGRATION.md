# 企微云端知识库迁移准备

## 起点

本分支从自动招呼 v1.4.9 对应提交创建。改动前的程序、实际工作目录、岗位配置、词库、运行环境、账本及发布密钥已安排本地完整备份；备份属于私有恢复资料，不纳入公开仓库。

本次提交只记录迁移方向和开发约束，不代表企微接入已经实现或经过真实账号验证。

## 用户确定的方向

把原先随 GitHub 下载流程分发的业务知识迁移到企微云端知识库。需要考虑每位使用者的接入，以及后续开放上传的能力。自动招呼使用岗位词库和评分配置；回复助手还需要岗位事实、人设、回复规则及独立的会话上下文。

## 必须区分的内容

1. 业务知识：企业/岗位资料、关键词组、扣分词、评分参数、回复参考资料。
2. 程序发布：工具代码、安装包、版本和签名验证。
3. 运行环境：Python、依赖包、OCR 等资源。

企微知识库迁移不能自动等同于取消所有 GitHub 地址。程序发布和依赖资源是否一起改用企微，需要在实现前明确。

## 实现前应确认

- 使用的企微企业、共享空间、文件类型及成员范围。
- 官方 API、MCP 或 CLI 中哪条路径满足完整读取、上传及权限要求。
- 两个独立使用者能否按预期读取和上传同一共享库；授权过期与失败如何反馈。
- 上传是否进入待发布区，正式版本由谁发布，个人自用内容如何隔离。
- 词库格式、版本标识、完整性校验和当前正式版本的定位方式。
- 本地缓存、网络失败、版本回退及个人修改的保留方式。
- 回复人设和事实资料分别维护；候选人的会话记录不能跨人混用。

## 运行约束

自动招呼应完整加载本轮适用词库，在启动时保存明确版本的规则快照。云端中途更新不能改变已开始运行的评分口径。候选人资料、账本及发布密钥不能因为更换知识来源而自动上传。

回复助手以当前岗位事实、独立人设、当前会话记录和回复规则共同生成内容。调用知识库检索不等于调用一个已经设置好人设和长期记忆的远端智能体；任何远端智能体方案都应先核实正式接口及上下文隔离能力。

## 验证目标

完成授权、完整下载、词库解析校验、两账号权限隔离、上传与发布版本切换、断网/授权失败，以及历史快照与本地修改保留的验证后，再考虑替换现有正式知识分发流程。
